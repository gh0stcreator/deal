## ONBOARDING

### Шаг 1: Вход в сценарий (`/start`, без активного флоу)
**Бот пишет:**
- `Привет.`
- `Я помогаю двум людям спокойно договориться, если обсуждать напрямую сложно.`
- `Как это работает:`
- `— каждый из вас сначала пишет свою версию отдельно`
- `— я собираю общую картину`
- `— помогаю вам найти решение`
- `Ваши сообщения не пересылаются друг другу напрямую.`
- `Готовы начать?`

**Контрол:** inline keyboard
- `Начать`

**Триггер перехода:** callback `menu:begin`

---

### Шаг 2: Выбор действия
**Бот пишет:**
- `Что вы хотите сделать?`

**Контрол:** inline keyboard
- `Создать договорённость`
- `Присоединиться по приглашению`
- `Посмотреть статус`

**Триггер перехода:** callback `menu:create | menu:join | menu:status`

---

### Шаг 3A: Создание — ввод темы
**Бот пишет:**
- `О чём хотите договориться? Опишите коротко.`

**Контрол:** просто текст без контролов (ожидание text input)

**Триггер перехода:** пользователь отправляет текст темы

---

### Шаг 3B: Создание — подтверждение темы
**Бот пишет:**
- `Я понял так:`
- `«{topic}»`
- `Это то, что вы хотите обсудить?`

**Контрол:** inline keyboard
- `Да, верно`
- `Хочу переформулировать`

**Триггер перехода:**
- `Да, верно` -> создание сессии
- `Хочу переформулировать` -> повторный ввод темы (`Отправьте формулировку ещё раз.`)

---

### Шаг 3C: Создание — готовое приглашение
**Бот пишет (сообщение 1):**
- `Готово.`
- `Отправьте следующее сообщение второму человеку 👇`

**Бот пишет (сообщение 2):**
- `{initiatorName} хочет обсудить с вами:`
- `«{problemTopic}»`
- `Нажмите на ссылку, чтобы подключиться:`
- `{deepLink | Не получилось создать ссылку в этом чате.}`

**Контрол:** inline keyboard
- `Если ссылка не сработает`
- `Посмотреть статус`

**Триггер перехода:**
- пользователь пересылает invite
- или callback `invite:details`

---

### Шаг 3D: Детали приглашения (fallback)
**Бот пишет:**
- `Ссылка для приглашения:` + `{deepLink}`
  или `Не получилось создать ссылку в этом чате.`
- `Если ссылка не сработает, отправь этот токен:`
- `{token}`

**Контрол:** просто текст без контролов

**Триггер перехода:** второй участник использует deep link/token

---

### Шаг 4: Присоединение по приглашению
**Бот пишет (сначала):**
- `Проверяю…`

**Бот пишет (успех):**
- `Вы подключились к договорённости.`
- `Дальше: нажмите «Подтвердить участие».`

**Контрол:** inline keyboard
- `Подтвердить участие`
- `Посмотреть статус`

**Триггер перехода:** callback `consent:{sessionId}`

---

### Шаг 5: Consent
**Бот пишет (сначала):**
- `Обрабатываю…`

**Бот пишет (если подтвердил только один):**
- `Вы подтвердили участие.`
- `Ждём второго человека.`

**Бот пишет (если подтвердили оба):**
- `Готово. Вы оба подтвердили участие.`
- `Дальше: ответьте на несколько коротких вопросов отдельно.`

**Контрол:** inline keyboard
- `Посмотреть статус`

**Триггер перехода:** state `CONSENTED` -> запуск intake вопросов для обеих сторон

---

### Статус (доступен с кнопки)
**Бот пишет (заголовок):**
- `Текущий статус:`

**Варианты текста:**
- `Пока подключён только один участник.`
- `Дальше: дождитесь второго человека.`
- `Сейчас каждый отвечает на вопросы отдельно.`
- `Дальше: завершите ответы, чтобы можно было собрать общую картину.`
- `Обе стороны подтвердили участие.`
- `Дальше: переходите к обсуждению решения.`
- `Второй человек подключился.`
- `Ждём, пока он подтвердит участие.`
- `Вы подтвердили участие.`
- `Ждём второго человека.`
- `Оба участника подключены.`
- `Ожидаем подтверждения.`
- `Дальше: нажмите «Подтвердить участие».`

**Контрол:**
- inline keyboard `Подтвердить участие` (показывается только invited стороне, если consent pending)
- иначе просто текст

**Триггер перехода:** callback `status:{sessionId}` / `menu:status`

---

## INTAKE

### Шаг 1: broad opening + вопрос `situation_facts`
**Бот пишет:**
- `Опишите ситуацию как есть, своими словами.`
- `Не подбирая формулировки — другой человек не увидит это сообщение напрямую.`
- `Чтобы зафиксировать базу: что конкретно сейчас происходит?`

**Контрол:** просто текст без контролов (ожидание text input)

**Триггер перехода:** пользователь присылает текст

---

### Шаг 2: смысловая рефлексия + подтверждение (общий паттерн)
**Бот пишет:**
- для `situation_facts`:
  - `Правильно понимаю, что сейчас конфликт крутится вокруг темы «{signalText}»,`
  - `и это уже влияет на ваш повседневный ритм?`
  - `Я понял правильно?`
- для `tension_point`:
  - `Похоже, главный острый момент для вас — как сейчас устроены «{signalText}»,`
  - `и из-за этого накапливается напряжение.`
  - `Я понял правильно?`
- для `important_need_or_interest`:
  - `Слышу, что для вас здесь ключевое — «{signalText}» и ощущение предсказуемости.`
  - `Я понял правильно?`
- для `hard_constraint`:
  - `Фиксирую: вариант, где нарушаются «{signalText}», для вас неприемлем.`
  - `Я понял правильно?`
- для `desired_outcome`:
  - `Понимаю, что рабочий для вас результат — ясные договорённости про «{signalText}».`
  - `Я понял правильно?`
- для `acceptable_flexibility`:
  - `Вижу, что в теме «{signalText}» вы готовы к ограниченной гибкости,`
  - `если это приведёт к стабильному решению.`
  - `Я понял правильно?`

**Контрол:** inline keyboard
- `Да, верно`
- `Хочу поправить`

**Триггер перехода:** callback `intake:confirm:{sessionId}:{stepId}`

---

### Шаг 3: переход на следующий вопрос
**Бот пишет:**
- `Принято. Идём дальше.`
- следующий вопрос по порядку

**Контрол:** просто текст без контролов

**Триггер перехода:** авто по step-machine

---

### Последовательность intake-шагов (точная)
1. `situation_facts` -> `Чтобы зафиксировать базу: что конкретно сейчас происходит?`
2. `tension_point` -> `Что в этой ситуации задевает вас сильнее всего?`
3. `important_need_or_interest` -> `Что для вас здесь важнее всего?`
4. `hard_constraint` -> `Что для вас в таком решении точно неприемлемо?`
5. `desired_outcome` -> `Какой результат для вас был бы рабочим?`
6. `acceptable_flexibility` -> `Где вы готовы быть гибкими, если это поможет договориться?`

**Что триггерит переход:** подтверждённый callback `Да, верно` на каждом шаге.

---

### Шаг редактирования ответа
**Бот пишет:**
- `Отправьте исправленный вариант.`

**Контрол:** просто текст без контролов

**Триггер перехода:** новый текст пользователя -> снова рефлексия + confirm кнопки

---

### Завершение intake одной стороны
**Бот пишет:**
- `Спасибо, ваша часть собрана.`
- `Сейчас ждём второго человека.`

**Контрол:** просто текст без контролов

**Триггер перехода:** ожидание complete intake второй стороны

---

## SYNTHESIS

### Шаг 1: показ общей нейтральной картины (обеим сторонам)
**Бот пишет:**
- `Похоже, вы оба хотите...`
- `{shared_goal}`
- `У вас уже есть общее в том, что...`
- `- {agreement_points...}`
- `Главная точка напряжения сейчас...`
- `{primary_tension_point}`
- `Похоже, рабочее поле для договорённости может быть таким...`
- `{possible_zone_of_agreement}`

**Контрол:** inline keyboard
- `Это похоже на правду`
- `Нет, нужно уточнить`

**Триггер перехода:** callback `synthesis:ok` или `synthesis:clarify`

---

### Шаг 2A: подтверждение synthesis
**Бот пишет:**
- `Спасибо. Зафиксировал.`

**Контрол:** просто текст

**Триггер перехода:** после реакций обеих сторон -> старт ISSUE_LOOP

---

### Шаг 2B: уточнение synthesis
**Бот пишет:**
- `Что именно я понял не так?`

**Контрол:** просто текст (ожидание text input)

**Если пришёл текст:**
- `Принял уточнение. Сохранил отдельно.`

**Триггер перехода:** сохранено уточнение; при наличии реакций обеих сторон -> ISSUE_LOOP

---

## ISSUE_LOOP

### Шаг 1: framing главного вопроса
**Бот пишет:**
- `Похоже, основной вопрос сейчас такой:`
- `{issue_title}`
- `С одной стороны важно...`
- `{side_a_priority}`
- `С другой стороны важно...`
- `{side_b_priority}`

**Контрол:** просто текст

**Триггер перехода:** автоматически за framing идёт блок вариантов

---

### Шаг 2: introduction вариантов
**Бот пишет:**
- `Вот варианты, которые могут сработать:`

**Контрол:** просто текст

**Триггер перехода:** далее отправляются option cards

---

### Шаг 3: карточка варианта (для каждого option)
**Бот пишет:**
- `Вариант: {title}`
- `{description}`
- `Компромисс: {tradeoff_note}`

**Контрол:** inline keyboard
- `Подходит`
- `Не подходит`
- `Хочу изменить`

**Триггер перехода:** callback `issue:react:*`

---

### Шаг 4A: реакция accept/reject
**Бот пишет (в зависимости от summary status):**
- `Похоже, есть рабочий вариант. Зафиксировал реакцию.`
- или `Пока рабочий вариант не найден. Зафиксировал реакцию.`
- или `Реакцию зафиксировал. Дальше ждём ответ второй стороны.`

**Контрол:** просто текст

**Триггер перехода:** при `WORKABLE_PATH_FOUND` -> запуск AGREEMENT

---

### Шаг 4B: реакция edit
**Бот пишет:**
- `Что именно в этом варианте нужно изменить?`

**Контрол:** просто текст (ожидание input)

**После input:**
- `Изменение зафиксировал. Похоже, рабочий вариант уже есть.`
- или `Изменение зафиксировал. Ждём реакцию второй стороны.`

**Триггер перехода:** если найден workable path -> AGREEMENT

---

## AGREEMENT

### Шаг 1: показ черновика договорённости (обеим сторонам)
**Бот пишет:**
- `Похоже, вы пришли к такому варианту:`
- `— {agreed_action_1}`
- `— {agreed_action_2}`
- `Границы:`
- `— {boundary_1}`
- `Если что-то пойдёт не так:`
- `— {fallback_rule}`
- `Можно пересмотреть:`
- `— {review_point}`
- `Подтверждаем договорённость?`

**Контрол:** inline keyboard
- `Подтверждаю`
- `Хочу изменить`
- `Не подходит`

**Триггер перехода:** callback `agreement:respond:*`

---

### Шаг 2A: confirm/reject outcome feedback
**Бот пишет:**
- `Готово. Договорённость подтверждена обеими сторонами.`
- или `Пока договорённость не получилась. Зафиксировал, что стороны не пришли к варианту.`
- или `Зафиксировал частичное согласие. Нужны уточнения по оставшимся пунктам.`
- или `Зафиксировал ответ. Ждём вторую сторону.`

**Контрол:** просто текст

**Триггер перехода:** по outcome доменной логики

---

### Шаг 2B: edit draft
**Бот пишет:**
- `Что именно нужно изменить?`

**Контрол:** просто текст (ожидание input)

**После input:** перегенерация draft и повтор шага 1

## EDGE_CASES

### `/start` в середине флоу
**Поведение:** бот делает resume активного шага, а не сброс.

**Возможные тексты:**
- `У вас уже есть активный сценарий. Отправьте ссылку-приглашение или токен.`
- `У вас уже есть активный сценарий. О чём хотите договориться? Опишите коротко.`
- `Продолжаем с текущего шага. Проверьте формулировку и подтвердите или поправьте.`
- `У вас уже есть активный шаг подтверждения.`
- `Продолжаем с текущего вопроса.`
- `У вас уже есть активный шаг уточнения. Что именно я понял не так?`
- `У вас уже есть активный шаг редактирования варианта. Что именно в этом варианте нужно изменить?`
- `У вас уже есть активный шаг изменения договорённости. Что именно нужно изменить?`
- `У вас уже есть активный сценарий. Показываю текущий статус.`

---

### Второй участник не подключился
**Поведение:** ожидание + статус/подсказка без продвижения.

**Тексты:**
- `Пока подключён только один участник.`
- `Дальше: дождитесь второго человека.`
- `Вы уже подключены. Нужен второй человек. Отправьте ему приглашение.`
- `Вы уже подтвердили участие. Нужен второй человек. Отправьте ему приглашение.`
- `Спасибо, ваша часть собрана. Сейчас ждём второго человека.`

---

### Пользователь долго не отвечает
**Поведение:** таймаута в UX нет; бот хранит state и продолжает с места остановки через `/start` или следующий input/callback.

**Контрол:** conversation state + resume сообщения (см. выше).

---

### Кнопка нажата дважды / stale callback
**Поведение:** идемпотентные ключи + защита stale step.

**Тексты:**
- `Это старое подтверждение. Продолжаем с актуального шага.`
- `Этот ответ уже подтверждён.`
- `Похоже, есть рабочий вариант. Зафиксировал реакцию.` (повторная безопасная фиксация)
- `Вы уже подтвердили участие.`

---

### Неожиданный input внутри активного шага

#### Если бот ждёт confirm, а пришёл текст
**Бот пишет:**
- `Сначала подтвердите текущую формулировку кнопкой ниже.`
- + текущая рефлексия

**Контрол:** inline keyboard `Да, верно / Хочу поправить`

#### Если пустой текст на шаге, где нужен ответ
**Бот пишет:**
- текущий вопрос
- или `Ответьте, пожалуйста, коротко на текущий вопрос.`

#### Если тема слишком длинная/пустая
**Бот пишет:**
- `Тема должна быть короткой: до 120 символов. Попробуйте ещё раз.`

#### Если invite не распознан
**Бот пишет:**
- `Похоже, в приглашении ошибка. Попробуйте ещё раз или откройте ссылку`

---

### Системные/ошибочные тексты (mapTelegramErrorText)
- `Вы не можете сделать это сейчас.`
- `Не получилось найти договорённость.`
- `Пока не хватает данных второй стороны. Ждём второго человека.`
- `Приглашение недействительно или устарело.`
- `Что-то пошло не так. Попробуйте ещё раз.`

---

### Общие системные сообщения
- `Проверяю…`
- `Обрабатываю…`
- `Неизвестная команда. Нажмите /start и выберите действие.`
- `Слишком много запросов. Попробуйте через несколько секунд.`
- `Не могу найти этот шаг. Отправьте ответ ещё раз.`
- `Кажется, шаг сбился. Давайте продолжим.`
- `Не получилось сохранить этот шаг. Давайте продолжим.`
- `Этот шаг устарел. Продолжаем по текущему сценарию.`
- `Сводная картина уже готова. Проверьте последнее сообщение.`
